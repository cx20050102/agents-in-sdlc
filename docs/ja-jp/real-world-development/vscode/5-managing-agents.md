Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、ツール呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、追加のプロンプトで作業を調整したり広げたりできます。エディターを離れる必要はありません。

この演習では、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッションの途中でエージェントに指示し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中に、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を最初から始めずに、進行中のセッションを案内して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順、調査したファイル、実行したコマンド、提案した編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャットに表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を戻し、もう一度作業するようエージェントに依頼します。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、問題のないコマンドだけを許可してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に変更の概要が表示されます。

## エージェントにライトモードを追加するよう依頼する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えも追加します。エージェントは前の作業内容、変更したコンポーネント、スタイル、ローカルストレージの使い方などのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを入力します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を調べ、ライトモードの追加を提案することを確認します。
3. ハイコントラストのときと同じように、新しい変更ごとにレビューして **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合は、チャット入力欄の横にある **Stop** ボタンで停止し、明確にするための追加メッセージを送信します。

> [!TIP]
> 作業中のセッションに追加のプロンプトを送ると、最初からやり直すより短時間で調整できます。たとえば、「CSS を簡素化して、セレクターの重複ではなく CSS 変数を使う」、「3 つ目の切り替えを作らず、既存の設定パネルにライトモードを追加する」、「両方の切り替えにキーボードショートカットも追加する」と依頼できます。

## 作業セットをレビューする

変更をコミットする前に、エージェントが編集したファイル全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保持など) が反映されていることを確かめます。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode で進行中のセッションを監視して案内しました。ファイル編集ごとにレビューし、変更を受け入れるか取り消し、コンテキストを維持したまま追加プロンプトを送って作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり取り消したりしました。
- 追加プロンプトを使って進行中のセッションを調整しました。

次は、アクセシビリティの作業を PR として公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
